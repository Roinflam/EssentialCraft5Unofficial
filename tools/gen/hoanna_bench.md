# 海纳尔区块生成开销基准

第六批 6a（batch6a.md §4.4 第 1 条）。目标是「结构距离合理、不卡」，这里量的是**区块生成**这一头：海纳尔每区块的生成开销不超过原版主世界（> 1.2 倍算回归）。

## 跑法

```
python tools/gen/hoanna_bench.py                  # 工程根目录、后台跑（要起 Gradle 和本地端口）；约 5~10 分钟（Gradle 配置 + 开服 + 2 轮 × 2 个维度）
python tools/gen/hoanna_bench.py --rounds 3       # 多跑几轮
python tools/gen/hoanna_bench.py --analyze run/hoanna_bench_<时间>   # 不开服，重新统计留下的录像
```

- 跑之前：`runData` 已经跑过（噪声设置 `essentialcraft5:hoanna` 是生成物，没有它海纳尔维度加载失败）；机器空闲（采两次 `Get-Process` 的 CPU 相减来确认；别的冒烟服、测试客户端、Gradle 都会搅乱数据）。
- 脚本临时改 `run/server.properties`（新存档 `hoanna_bench_<时间>`、种子 20260929、只听 127.0.0.1、端口 25995 / RCON 25996、关看门狗、视距 / 模拟距离 2），
  没有 `run/eula.txt` 就临时写一个；跑完还原。**被打断以后**（硬杀 python 不走 finally）：下次运行一开头按 `run/server.properties.hoanna_bench_backup`
  和 `run/eula.txt.hoanna_bench_made` 还原然后退出；重跑前先查有没有留下的 runServer / Gradle 进程（按命令行核对是本工程的 java 再结束）。同一时间只跑一个。
- 存档留在 `run/hoanna_bench_<时间>`（里面有 `hoanna_bench_meta.json` 和 `run/debug/*.jfr` 录像的路径），要重算就 `--analyze`；不要了可以删。

## 量法

每轮在从没生成过的地方（区块 (2500 + 轮 × 65, 2500) 附近，两个维度同一块坐标）forceload 25 × 25 区块，一个维度一段 JFR 录像（`/jfr start` … `/jfr stop`），
抽样 `execute if loaded` 等全部生成完。轮与轮之间主世界 / 海纳尔的先后顺序轮换（JIT 热身、磁盘缓存对先跑的不利）。

统计用 JDK 的 `jfr print --json --events minecraft.ChunkGeneration`，按事件的 `level` 字段只取这个维度、这块区域外扩 12 区块的事件
（1.20.1 自带的 `jfr-report-server-*.json` 把所有维度的 chunkGen 合在一起，分不开——batch6a.md §4.4 核查）：

| 指标 | 含义 | 注意 |
|---|---|---|
| `sum_seconds` | 所有生成阶段事件的耗时之和 | 噪声、地物等阶段丢给后台线程池，事件耗时含排队，绝对值偏大；两个维度一样偏，看比值 |
| `wall_seconds` | 第一个事件开始到最后一个结束 | 整块区域的墙钟 |
| `poll_seconds` | forceload 到抽样全部加载完（3 秒一次轮询） | 粗，只作旁证 |
| `per_status` | 各阶段（noise、surface、carvers、features……）的次数与耗时 | 定位是哪一步慢 |

结果写 `tools/gen/hoanna_bench_result.json`，终端打印每轮的「海纳尔 / 主世界」比值和平均：≤ 1.0 通过、≤ 1.2 警告、> 1.2 回归。

## 什么时候跑

1. **F6a 合入时跑一次「只有地形」的基线**（验证 D1 A′：噪声复制到 `essentialcraft5:hoanna/…` 后开销和原版一样）：这时海纳尔群系只有原版地物，还没有 EC 结构、EC 地物。
2. **集成时跑全量**（七个模块都合入后，含三种结构、EC 矿与上古遗迹、植物），另按 batch6a.md §4.4 做「结构集 frequency 0 对照差 < 5%」（数据包覆盖三个 `structure_set` 的 frequency 后再跑一次）。

主世界那一半是原版 + 整合进 `run/mods` 的东西（开发环境只有本模组、Curios、TestHelper），海纳尔 multi_noise 只有 7 个参数点、没有原版结构集，预期比主世界略快。

**刷怪钩子 `HoannaSpawnHooks`（第十三批 13d，按代码估算，没实测）**：本基准只量区块生成，不含自然刷怪。按 1.20.1 `NaturalSpawner` 推：
怪物没到上限时，每个可刷区块每刻取一个随机点，落在实心方块里不发事件；落在空气里时 3 组 × 每组最多 4 次尝试，
每组先在 `getRandomSpawnMobAt` 发一次 `PotentialSpawns`，之后每次尝试的 `canSpawnMobAt` 判位置之前再发一次。
单人约 200 个可刷区块，折合每刻约 150~300 次事件。要改表时（潮位不是 0.5、有毒雾）每次复制约 10~13 条的表、逐条判一次标签、
本地怪各做两次 remove / add 和两次哈希查找（黑暗 / 风暴再加一次 `nearbyCount` 查表和一次 `getBiome`），约 0.3~1 µs；
合计**每名玩家每刻约 0.05~0.3 ms**，到上限后为 0，在 batch13.md §7.3「刷满时 +0.5 ms」的预算内。
潮位 0.5（或关掉 `tide_weights`）、又没有毒雾时不复制表、不逐条判标签（黑暗 / 风暴只做追加那一步）。
有客户端测试时用 spark 量一次：海纳尔刷满前后各 5 分钟、每刻中位数（`cancel` 结束采样，不用 `stop`）。
